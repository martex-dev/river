# Security review — River 1.0.28

Scope: the community word filter and suspicious link warnings. Internal
review; not an independent audit.

| Area                    | Check                                                                                                                                                                                                  | Result                     |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------- |
| Word filter storage     | The list is sealed inside the community onboarding blob, so the server never sees it; changing it needs `MANAGE_COMMUNITY` (existing route)                                                            | ✅ review                  |
| Word filter enforcement | Applied by each River app because the server cannot read messages. A modified client can ignore it; the settings text says so and the UI does not present it as server-enforced                        | ✅ `word-filter.test.ts`   |
| Word filter matching    | Folds case, accents and look-alikes; filter words are regex-escaped and matched literally (whole words), so no user-controlled patterns or ReDoS                                                       | ✅ `word-filter.test.ts`   |
| Link warnings           | Parsed with the WHATWG `URL` parser in main; flags punycode (`xn--`) and look-alike hosts, raw IPs, known shorteners and plain http. A warning, not a guarantee: links that pass are not called "safe" | ✅ `link-warnings.test.ts` |
| Opening links           | Still only `http(s)` via `shell.openExternal` after the existing validation; the warning adds a step and removes none                                                                                  | ✅ review                  |

Dependencies: Dependabot reports a medium-severity denial-of-service issue in
`sprintf-js` (no patched version yet). It is reached only through development
tooling and is not bundled in the app or the server image.

No new metadata visible to the server. No critical issue is open for 1.0.28.
