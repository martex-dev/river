# Security review — River 1.0.16

Scope: voice reliability (seat grace period, heartbeats, queued signals,
self-healing connections), the encrypted voice relay, startup reliability,
the packaged self-test and the connection check. Internal review; not an
independent audit.

| Area                  | Check                                                                                                                                                                                                                | Result                                         |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| Relay confidentiality | Voice frames are AES-256-GCM sealed in the renderer with a random per-call sender key; keys travel only inside sealed signals to the people relayed with; the server forwards opaque bytes                           | ✅ `relay.test.tsx`, e2e (decoded audio)       |
| Relay integrity       | Sender River ID and sequence are associated data; tampered, re-attributed, re-sequenced or replayed frames are rejected                                                                                             | ✅ `relay.test.tsx`                            |
| Relay authorization   | The server forwards a frame only to recipients in the sender's own voice channel; strangers and people outside voice receive nothing                                                                               | ✅ `communities.test.ts`                       |
| Relay abuse           | Separate per-connection frame budget (drops, never closes), payload cap (1200 bytes), max 24 recipients, frames dropped for slow readers (256 KiB buffered), nothing stored                                        | ✅ `communities.test.ts`                       |
| Relay IPC             | Renderer → main frames are fire-and-forget but still sender-checked (trusted frame), recipients zod-validated as UUIDs (≤ 24), payload size-checked; sent only while in a voice channel and online                  | ✅ code review                                 |
| Seat grace period     | A held seat expires after 45 s; deliberate leave frees it at once; moderation disconnect is unchanged; a rejoin within grace passes the same permission and user-limit checks as any join                          | ✅ server + real-socket tests                  |
| Heartbeats            | Server pings terminate unresponsive sockets (their seat enters grace); client pings detect silent sockets; no new data is sent                                                                                      | ✅ real-socket tests                           |
| Queued signals        | At most 400 sealed signals, 30 s old at most, held only in memory; dropped on deliberate leave                                                                                                                     | ✅ integration test                            |
| Startup               | Fatal startup errors show a dialog and exit (no lingering process holding the single-instance lock); the details shown are an error message and stack lines, never data; GPU fallback state is a local flag file | ✅ `startup-guard.test.ts`                     |
| Self-test             | `--self-test` uses a throwaway profile in the temp folder, makes no network requests, and exits                                                                                                                     | ✅ run on packaged builds (CI, local Windows)  |
| Connection check      | Reports contain statuses, latencies and advice; no server address, token, username list or content; probes only the user's own server, the address relay and public STUN servers already used for calls         | ✅ `diagnostics-main.test.ts`, code review     |
| Test-only switch      | `__riverForceRelay` can only make the renderer's own calls avoid direct connections; it grants nothing                                                                                                              | ✅ code review                                 |

New metadata visible to the server: who relays voice to whom, when, and frame
sizes (THREAT_MODEL §5e). Residual risks otherwise unchanged. No critical
issue is open for 1.0.16.
