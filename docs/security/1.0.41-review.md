# Security review — River 1.0.41

Scope: voice presence across connection drops, account recovery, "Open in River"
links, the invite landing page and River's permanent link address. Internal
review; not an independent audit.

| Area             | Check                                                                                                                                                                                                                                                | Result                                               |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| Voice presence   | People stay in the call view while their connection is rebuilt; no new data leaves the device and the relay is unchanged (sealed with per-call sender keys, only to people in the same channel or call room)                                         | ✅ `voice-resilience.spec.ts`, `voice-mesh.test.tsx` |
| Account recovery | "Set up my account again" only after the server refused this account; it is the person's choice, forgets only the account row and pinned server identity on this device, and creates a new account the normal way                                    | ✅ `account.test.ts`                                 |
| river:// links   | Only `river://open?link=` with an invite, friend or sign-up link is accepted (strict parsers, 4 KB cap); nothing happens without the person confirming in River; links wait until River is unlocked and set up                                       | ✅ `deep-link.test.ts`                               |
| Invite page      | The invite secret stays in the URL fragment, which browsers never send to the server; the one inline script is allowed by its hash (`default-src 'none'`); no cookies, analytics or third-party requests                                             | ✅ `landing.test.ts`                                 |
| Permanent links  | Links on River's home server use https://martex-dev.github.io/river (static pages, no server code). The app treats that address as "River's home server" and still reaches it only through signed address notes verified against the pinned identity | ✅ `community.test.ts`, `home-server.test.ts`        |
| Release files    | Version-less installer copies are hashed into the signed release manifest and SHA256SUMS like every other file; updates still use the versioned files                                                                                                | ✅ release workflow                                  |

Residual risks: the home server's free quick tunnel still drops every connection
every few minutes; River now rides through those drops, and a steadier address
remains a maintainer decision (THREAT_MODEL §7). No critical issue is open for
1.0.41.
