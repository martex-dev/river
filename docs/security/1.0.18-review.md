# Security review — River 1.0.18

Scope: notification settings, appearance, community folders, image viewer,
scheduled events, reply @ON/OFF, View reactions, polls, richer profiles,
account deletion, and the message-edit key fix. Internal review; not an
independent audit.

| Area                 | Check                                                                                                                                                                                                                   | Result                                                     |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| Account deletion     | Needs a session and a fresh one-time challenge signed by a device key under `river-delete-account-v1`; wrong key, reused challenge, missing proof and missing session are refused; no branch on the raw token           | ✅ `delete-account.test.ts`, CodeQL clean                  |
| Deletion scope       | One shared purge for operator and self: leaves communities (owned ones deleted), removes keys, devices, sessions, reactions, event interest, bans, blocks, mail; the app forgets the account and stops auto-registering | ✅ integration test                                        |
| Events               | Name, description and place sealed (`event:<id>` AAD); server sees times, channel ID, creator, interest list; `MANAGE_EVENTS` enforced on the server; events in hidden voice channels are hidden                        | ✅ `communities.test.ts`, integration (no plaintext in DB) |
| Polls                | Question and answers in the sealed message body; votes are sealed reactions with a marker the server cannot see; late or double votes by a modified app are bounded (single-choice counts once)                         | ✅ `poll.test.ts`, integration (no plaintext)              |
| Profiles             | About me, pronouns, banner inside the sealed profile; values length-checked and validated on read                                                                                                                       | ✅ integration (no plaintext)                              |
| Reply @OFF           | Inside the sealed body; only affects the reader's own mention computation                                                                                                                                               | ✅ integration                                             |
| Edits                | Sealed with the message's own key, so its reactions' tags keep matching; poll messages cannot be edited                                                                                                                 | ✅ integration                                             |
| Notifications        | Per-place levels and mutes are local settings (strict schema); no new data leaves the device                                                                                                                            | ✅ `notify-rules.test.ts`                                  |
| Appearance / folders | Local settings only (strict schemas); zoom applied by main from validated settings                                                                                                                                      | ✅ `rail.test.ts`, review                                  |
| Image viewer         | Copy image redraws the already-decrypted picture on a canvas; no network request (CSP `connect-src 'self'` unchanged)                                                                                                   | ✅ review                                                  |

New metadata visible to the server: event times and interest lists
(THREAT_MODEL §5f). Residual risks otherwise unchanged. No critical issue is
open for 1.0.18.
