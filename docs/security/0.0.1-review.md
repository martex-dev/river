# Security review — River 0.0.1

**Scope:** desktop shell hardening, IPC, settings storage, update pipeline,
release signing, CI/CD. **Not in scope:** messaging, crypto identity, server
(not yet implemented). Internal review; not an independent audit.

## Checked

| Area                | Check                                                                                                                                                                           | Result                                                                            |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| Renderer isolation  | `sandbox`, `contextIsolation`, no `nodeIntegration`, separate session partition                                                                                                 | ✅ e2e: no `require`/`process` in renderer                                        |
| Content loading     | UI served from `river://app/` with CSP `default-src 'none'; script-src 'self'` … no `unsafe-inline`/`unsafe-eval`                                                               | ✅ e2e: header present, inline script blocked                                     |
| Path traversal      | `resolveAppPath` rejects encoded separators / NUL; `..` normalised inside root                                                                                                  | ✅ unit tests                                                                     |
| Navigation          | `will-navigate`/`will-redirect` fail closed; `window.open` denied; `<webview>` blocked                                                                                          | ✅ e2e; fixed a fail-open case where an empty dev-server URL made the guard throw |
| Network from UI     | All http(s)/ws(s) requests from the UI session cancelled (except the dev server in development)                                                                                 | ✅ e2e                                                                            |
| Permissions         | Camera/mic/notifications/devices denied by default in both sessions                                                                                                             | ✅ code review                                                                    |
| IPC                 | Fixed channel list; sender must be River's top-level frame; settings patch strictly validated; links limited to a fixed allow-list                                              | ✅ unit + e2e (invalid patch rejected)                                            |
| Binary hardening    | Electron fuses: no RunAsNode, no `--inspect`, no `NODE_OPTIONS`, asar-only + integrity validation, cookie encryption                                                            | ✅ packaged check (`ELECTRON_RUN_AS_NODE` ignored)                                |
| Update authenticity | Ed25519 signature over domain-separated manifest bytes, verified before parsing; key-ID/public-key consistency enforced; exact version match; downloaded SHA-512 must be listed | ✅ 15 + 7 unit tests incl. tampering, wrong key, replay, swapped file             |
| Downgrade           | electron-updater enables `allowDowngrade` when a channel is set — River resets it and enforces strictly-newer itself                                                            | ✅ unit tests                                                                     |
| Install timing      | electron-updater would register install-on-quit at download time (before River's check); River disables it and installs on quit only after verification                         | ✅ unit tests                                                                     |
| Metadata fetch      | Manifest downloads capped at 512 KiB; version URL-encoded                                                                                                                       | ✅ unit tests                                                                     |
| Release pipeline    | Tag/version check, tests before build, actions pinned by SHA, least-privilege `permissions`, signature self-verified against pinned keys before publishing                      | ✅ workflow review                                                                |
| Secrets             | Signing key never in the repo (`.gitignore` covers keys/env); generator refuses to write inside the repo                                                                        | ✅                                                                                |
| Logging             | Local only; redaction of PEM keys/tokens; no content exists yet                                                                                                                 | ✅ unit tests                                                                     |
| Privacy             | No telemetry; fonts bundled; Chromium's network spellchecker disabled; only network traffic is the update check to GitHub                                                       | ✅                                                                                |

## Residual risks

1. Release key in GitHub Actions secret — compromise of the maintainer's GitHub
   account could lead to a malicious signed release. Mitigation planned before 1.0.0.
2. No Authenticode / notarization — users must bypass OS warnings on first install,
   which trains them to click through warnings. Mitigation depends on funding.
3. No automatic rollback after a verified update that fails to start.
4. Dev-only dependency advisories (electron-builder → sprintf-js, moderate DoS) —
   build tooling only, not shipped.
