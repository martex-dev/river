# Security review — River 1.9.0 (Stage 2)

Scope: everything Stage 2 added up to 1.9.0 — the phone apps (Android 1.1,
iPhone 1.3), linked devices (1.2), phones day to day (1.4), identity-bound
call setup and safer linking (1.5), contact sync (1.6), ringing calls (1.7)
and remote assistance (1.8). Internal review (a separate reviewing agent read
the code without changing it, then the fixes were made and tested); not an
independent audit.

## Findings and what was done

| Severity    | Finding                                                                                                                    | Fix                                                                                                                                                       | Released     |
| ----------- | -------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------ |
| High        | A removed linked device kept its open realtime connection (sockets authenticate once)                                      | The hub records each socket's device; removing devices closes their sockets at once (`apps/server/test/linked-devices.test.ts`)                           | 1.3.1        |
| Medium      | Device lists could be rolled back by a server replaying an older signed list                                               | Clients keep the newest version seen for their own and each person's list and refuse older ones; `deviceList()` also checks the River ID                  | 1.3.1        |
| Medium      | The removal message promised more than removal does                                                                        | Plain wording; ADR 0006 states that identity and community keys are not rotated on removal                                                                | 1.3.1        |
| Medium      | Identity-bound call signals: stripping before the first pin; pins poisoned from community profiles (not bound to a person) | Only libsignal-held identity keys are trusted; for those people a valid signature no older than ten minutes is required; others stay on the community key | 1.5.0        |
| Low         | Call signals could be replayed                                                                                             | Time inside the signed bytes, ten-minute window                                                                                                           | 1.5.0        |
| Low/Medium  | Anyone could fill every link mailbox slot without an account                                                               | The offering device reserves its slot (signed in, three per account); unreserved codes from older apps are capped per address                             | 1.5.0        |
| Low         | A web page could open `river://link` and pull a fresh install into someone else's account                                  | The code's server is shown before joining, and the new device asks "Is this you?" (name, server, River ID) before adopting the account                    | 1.3.1, 1.5.0 |
| Medium/High | Remote assistance: a compromised page could take a screen without the picker and hide the sharing bar                      | Main asks a native "Share your screen?" before every capture, there is no default screen, and the bar reopens if it crashes                               | 1.8.0        |
| Low         | Android: any app could fake a tap on River's notifications                                                                 | A random secret per notification, compared in constant time                                                                                               | 1.4.0        |
| Low         | Android: `content://0@…fileprovider` URIs could pass Share → River's own-files check                                       | Authorities with `@` are refused; River's own authorities by package name                                                                                 | 1.4.0        |

## Checked, no problem found

- Link codes: the MAC comparison is constant-time; hello and provisioning are
  bound to the secret (HMAC, HPKE associated data); nothing secret is logged.
- Remote assistance pages: names are escaped, the pages have a strict CSP and
  no preload; `ping` coordinates are validated numbers, so the
  `executeJavaScript` call cannot be injected; point signals are accepted only
  while sharing, only from participants, at most four a second.
- Android: both foreground services and the reply receiver are not exported;
  PendingIntents are explicit (the reply action is mutable only because
  RemoteInput needs it, and it targets River's own receiver); the FileProvider
  is limited to `cache/shared/`; `openUrl` allows only http and https.
- Contact sync and sent-message copies are accepted only from this account's
  own devices; a copy never unblocks or removes anyone.

## Residual risks (see THREAT_MODEL.md §7)

- Every linked device holds the identity key and the community keys; removal
  relies on the server and does not rotate keys.
- After the person confirms a screen share, a page taken over later could hide
  the bar early (main cannot observe the capture ending).
- Community call setup from people River holds no libsignal key for rests on
  the community key, as before 1.5.
- The Android APKs are signed with a one-off preview key until the maintainer
  creates the permanent key; the iPhone app is an unsigned .ipa for sideloading.
- No independent audit yet.

No critical issue is open for 1.9.0.
