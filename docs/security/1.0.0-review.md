# Security review — River 1.0.0

Scope: what changed after the pre-1.0 review ([0.9.0-review.md](0.9.0-review.md)) —
channel categories, the layout endpoint used by drag and drop, per-channel
last-message times, local read markers, and the release-signing plan.
Method: code review of the new server routes, IPC actions and renderer code,
plus the tests listed below. This is an internal review, not an independent audit.

## Checks

| Area                   | Check                                                                                                                                                                                                                | Result                                                   |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| Category names         | Sealed with AES-256-GCM under the community key, AAD purpose `category:<id>`, so the server cannot read them or move them between categories, channels or communities                                                | ✅ code review; integration test decrypts on another app |
| Category routes        | Create, rename and delete require `MANAGE_CHANNELS`; IDs are validated; deleting a category only clears `parent_id` on its channels; per-community cap of 50                                                         | ✅ `communities.test.ts`                                 |
| Layout endpoint        | Requires `MANAGE_CHANNELS` in the community **and** on every channel it moves (channel overwrites can deny it); every channel and category must belong to the community; bounded arrays (100 / 500); one transaction | ✅ `communities.test.ts`                                 |
| Category visibility    | A category is only sent to members who can see one of its channels, who may manage channels, or when it is empty — a private channel's category name does not reach people who cannot see the channel                | ✅ `communities.test.ts`                                 |
| Last-message times     | Sent only for channels the member may view; reveals nothing beyond what loading the channel already shows                                                                                                            | ✅ code review                                           |
| Read markers           | Stored only in the local SQLCipher database (`channel_reads`), never sent to the server; renderer can only ask to mark a channel read (zod-validated channel ID)                                                     | ✅ integration test (restart)                            |
| Renderer               | Drag-and-drop data stays inside the app (`text/plain` channel IDs, ignored on drop from outside); collapsed-category state in `localStorage` holds only IDs                                                          | ✅ code review                                           |
| Backward compatibility | 0.9 clients ignore the new fields and keep working against a 1.0 server                                                                                                                                              | ✅ zod object stripping; code review                     |

## Residual risks (unchanged, documented to users)

- No sealed sender; the server sees who messages whom and when (THREAT_MODEL.md §5).
- One community key per epoch; anyone holding a current invite link can join and read.
- Release signing key in a GitHub Actions secret; hardening plan in
  [release-signing.md](release-signing.md) needs the maintainer.
- No Authenticode / Apple notarization; no independent audit.

No critical issue is open for 1.0.0.
