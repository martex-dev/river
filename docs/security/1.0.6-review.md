# Security review — River 1.0.6

Scope: timeouts, the audit log, category permissions with synced channels,
hoisted/mentionable role flags, per-community nicknames and the `/add` page.
Internal review of the new routes, model changes and app code; not an
independent audit.

| Area          | Check                                                                                                                                                                                        | Result                                     |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| Timeouts      | Require _Time out members_ and outranking the target; owner and administrators cannot be timed out; at most 28 days; enforced in the server's permission check, voice disconnected           | ✅ `communities.test.ts`                   |
| Audit log     | Readable only with _View audit log_; stores actor, action, target ID and numbers only (no names, no content); 90-day retention; written after the change succeeds                            | ✅ test asserts no profile/body/meta in it |
| Category sync | A synced channel's effective overwrites are the category's, computed on the server for every check; editing a channel's own overwrites unsyncs it; deleted roles are removed from categories | ✅ `communities.test.ts`                   |
| Role flags    | Mentionable and hoist live inside the sealed role name; the server never sees them. Mention rights are checked on the receiving client against the sender's permissions                      | ✅ integration tests                       |
| Nicknames     | Stored in the local SQLCipher database and sealed into the community profile; never sent elsewhere                                                                                           | ✅ integration test                        |
| `/add` page   | Static HTML with `default-src 'none'`; the River ID is in the URL fragment, which browsers never send to the server                                                                          | ✅ test                                    |

**Metadata note:** the audit log is new metadata on the server: who moderated
whom and when, and role and channel IDs. It holds no names or content, and it
is only readable by people the community trusts with _View audit log_.
THREAT_MODEL.md already lists community membership and roles as visible to the
server; this adds administrative timing.
