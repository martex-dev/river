# Security review — River 1.0.31

Scope: invite tracking and revoking invites. Internal review; not an
independent audit.

| Area         | Check                                                                                                                                              | Result         |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- | -------------- |
| Invite codes | Still stored only as SHA-256 hashes; the new public invite ID is random and unrelated to the code, so listing invites never reveals a working link | ✅ review      |
| Listing      | `GET /communities/:id/invites` needs `MANAGE_COMMUNITY`; it shows who made each invite, uses, expiry and which current members joined with it      | ✅ server test |
| Revoking     | Allowed for the invite's creator or `MANAGE_COMMUNITY`; audited (`invite.revoke`); members who already joined stay                                 | ✅ server test |

New metadata on the server: which invite a member joined with, and who made
each invite and when. It already knew who joined and when, and invites were
already created by signed-in members. No critical issue is open for 1.0.31.
