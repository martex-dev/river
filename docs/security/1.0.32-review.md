# Security review — River 1.0.32

Scope: end-to-end-encrypted incoming webhooks (ADR 0004,
THREAT_MODEL §5j). Internal review; not an independent audit.

| Area             | Check                                                                                                                                                                             | Result                 |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------- |
| No plaintext     | Outside services seal posts with AES-256-GCM under the webhook key (AAD binds community and channel); the server stores ciphertext only                                           | ✅ unit + e2e          |
| Secrets          | Key and token live only after `#` in the webhook address; the server stores a SHA-256 hash of the token and the key sealed with the community key; River shows the address once   | ✅ server test, review |
| Posting          | Bearer token compared in constant time; 30 posts a minute per webhook, from any number of addresses; text channels only (no voice or forum); message size limits as for members   | ✅ server test         |
| Management       | Create and delete need `MANAGE_CHANNELS` in that channel; up to 15 active webhooks; audited; deleting stops the token at once and keeps the sealed key so old posts stay readable | ✅ server test         |
| Display          | Posts carry a WEBHOOK badge and the webhook's name, never the creator's; they cannot be edited by anyone                                                                          | ✅ server test, e2e    |
| Reference script | `scripts/webhook/post.mjs` uses only Node `crypto` and `fetch`; strips the `#` part before sending                                                                                | ✅ unit                |

No critical issue is open for 1.0.32.
