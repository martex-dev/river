# Security review — River 1.0.1 to 1.0.9

Scope: everything added in the 1.0.x series up to 1.0.9, building on the
per-release notes [1.0.6](1.0.6-review.md) and [1.0.8](1.0.8-review.md).
Internal review of every new IPC action, server route, local table and
renderer surface; not an independent audit.

| Area                    | Check                                                                                                                                                                | Result                                |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------- |
| New IPC actions         | Every action (templates, icons, nicknames, mentions, threads, timeouts, audit, outbox, mark read/unread, reconnect) is a strict zod schema parsed in main            | ✅ code review; malformed-action test |
| Sealed metadata         | Community icon, role flags (mentionable, hoist), category and thread names are sealed with the community key under their own AAD purpose; the server never sees them | ✅ integration tests                  |
| Mentions                | Role, @everyone and @here pings are honoured only if the sender's permissions allow them; computed on the receiving device                                           | ✅ integration test                   |
| Server authorization    | Threads, announcements, slowmode, user limits, timeouts, category permissions and the audit log are enforced on the server, not only hidden in the UI                | ✅ `communities.test.ts`              |
| Local data              | Read markers, nicknames, the outbox (including attachment keys) and the pinned server identity live only in the SQLCipher database                                   | ✅ integration tests                  |
| Paste-to-join / friends | The clipboard is read only on an explicit paste outside text fields; joining and friend requests always ask first                                                    | ✅ e2e                                |
| Celebrations and sounds | No new network access; reduced motion respected; WebAudio only                                                                                                       | ✅ code review                        |
| Errors                  | `friendlyError` never forwards internal messages (paths, SQL) to the screen                                                                                          | ✅ `errors.test.ts`                   |
| Updates                 | A crash loop after an update pauses automatic installs; verification of signed updates is unchanged                                                                  | ✅ `update-service.test.ts`           |

Residual risks are unchanged from 1.0.0 plus the relay metadata noted in
THREAT_MODEL §5a. No critical issue is open for 1.0.9.
