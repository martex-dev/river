# Security review — River 1.0.22

Scope: soundboard, forum channels, stage channels, temporary bans, the
keybind editor, and the fix for permission refusals ending calls. Internal
review; not an independent audit.

| Area           | Check                                                                                                                                                                                                                                        | Result                                                     |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| Soundboard     | Name, emoji and clip sealed with the community key (`sound:<id>` AAD); `MANAGE_EXPRESSIONS` for upload, rename and delete (audited); ≤ 48 sounds, ≤ 240 KB sealed; clips validated as audio data URLs on read and played with `<audio>` only | ✅ `communities.test.ts`, integration (no plaintext in DB) |
| Playing sounds | `voice.sound` needs a voice seat, `SPEAK` in that channel, not server-muted or timed out, a sound of that community, and a 2.5 s per-person cooldown; the server relays only the sound ID to that channel's participants                     | ✅ `communities.test.ts` (sockets)                         |
| Forums         | `forum` flag changes need `MANAGE_CHANNELS` (existing route); a post's thread is created in the same transaction as its message; forums refuse top-level messages without one; titles and tags sealed                                        | ✅ `communities.test.ts`, integration                      |
| Stages         | Audience members are server-muted by the server on joining (not by their client) and the mute is lifted when they join a normal channel; only the audience can raise hands; `speaker` changes need `MUTE_MEMBERS` and to outrank the target  | ✅ `communities.test.ts` (sockets)                         |
| Temporary bans | Only fixed lengths; the server refuses rejoining until `until`, forgets expired bans, hides them from the list; audited                                                                                                                      | ✅ `communities.test.ts` (clock-controlled)                |
| Keybinds       | Local settings with a strict combo schema; combos typing could trigger are refused; built-in clashes reported                                                                                                                                | ✅ `keybinds.test.ts`                                      |
| Refusals       | A generic `forbidden` ends the call only while a voice join is pending (servers before 1.0.8); otherwise it is shown as a notice                                                                                                             | ✅ review, e2e                                             |

New metadata visible to the server: which sound ID someone played and when,
the number of sounds per community, who is on stage and who raised a hand,
and when a temporary ban ends. No critical issue is open for 1.0.22.
