# Security review — River 1.0.24

Scope: rules screening and onboarding, self-assignable roles, bulk message
delete, audit log filters, stickers. Internal review; not an independent
audit.

| Area            | Check                                                                                                                                                                                                                                                                                                        | Result                                                     |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------- |
| Rules screening | Rules and welcome note sealed (`onboarding` AAD) in their own field, so older clients' 2 KB metadata limit is untouched; the server makes newcomers of screened communities read-only (`VIEW_CHANNELS` only) until they accept; owners and administrators are never held; existing members count as accepted | ✅ `communities.test.ts`, integration (no plaintext in DB) |
| Self-roles      | Changing the list needs `MANAGE_COMMUNITY`; offered roles cannot carry any moderating or managing permission and must sit below the offerer's highest role; members can only add or remove roles from the list, never others; pending members cannot pick roles; audited                                     | ✅ `communities.test.ts`                                   |
| Bulk delete     | `MANAGE_MESSAGES` in that channel; only IDs from that channel are deleted (others ignored); ≤ 100; threads kept consistent; one audit entry with the count                                                                                                                                                   | ✅ `communities.test.ts`                                   |
| Audit filters   | Client-side over entries the person may already see; copying is local                                                                                                                                                                                                                                        | ✅ `audit-filter.test.ts`                                  |
| Stickers        | Name and picture sealed (`sticker:<id>` AAD); `MANAGE_EXPRESSIONS`; ≤ 60; pictures validated as image data URLs on read and shown with `<img>`                                                                                                                                                               | ✅ `communities.test.ts`, integration                      |

New metadata visible to the server: whether a community screens newcomers,
which role IDs are self-assignable, who has not accepted yet, and sticker
counts and sizes. No critical issue is open for 1.0.24.
